# Security notes

This is a prototype for non-production accounts. This file lists the controls that are implemented, the
deliberate gaps, and every cdk-nag acknowledgement with its reason.

## Implemented controls

| Area | Control |
|---|---|
| Entry points | App API requires a Cognito ID token (user pool authoriser); request bodies validated against JSON schemas; stage throttling; AWS WAF (managed common and known-bad-input rule groups, per-IP rate rule). The simulated platform API requires an API key and a usage plan, behind the same WAF. |
| IAM | One role per function; resource-scoped statements (tables, topics under the project prefix, the one runtime, the one memory, the one cache and cache user). No IAM users, no access keys. `InvokeAgentRuntimeForUser` only on the orchestrator role and only for this runtime. Runtime and gateway service roles trust `bedrock-agentcore.amazonaws.com` with `aws:SourceAccount` (and `aws:SourceArn` for the runtime). |
| Network | Lambdas that need the cache run in private subnets; the Lambda security group has no ingress and egress only to the cache (6379) and HTTPS (443). The cache security group accepts 6379 only from the Lambda security group. No `0.0.0.0/0` ingress anywhere. VPC flow logs enabled. DynamoDB gateway endpoint. |
| Data | DynamoDB with encryption at rest and point-in-time recovery; ElastiCache Serverless (encryption in transit and at rest, IAM authentication, restricted access string); Secrets Manager for the API key and the M2M client secret; SQS dead-letter queue with SSE and TLS-only policy; log groups with retention. No S3 buckets are created by the stack (CDK bootstrap assets only). |
| Application | UUID whitelist, command and parameter validation, contradiction handling, action cap, per-action sensitive-action policy with single-use confirmation tokens, same-name ambiguity guard, fixed fallback for malformed output, reply text from dispatch results, deterministic memory writes. |
| Observability | X-Ray tracing on Lambdas and API stages; access logs; EMF metrics for latency segments and hard-check counters; acceptance-latency alarm. |

## Known gaps (prototype scope)
* No automatic secret rotation (API key, M2M client secret).
* No MFA or Cognito threat protection; demo users only.
* The simulated platform API is internet-facing (needed for the AgentCore Gateway OpenAPI target); in a real
  integration it is the customer's existing API with its own authentication.
* The voice channel is exercised with developer IAM credentials; no device certificates or IoT policies are
  provisioned.
* AWS managed policies `AWSLambdaBasicExecutionRole` / `AWSLambdaVPCAccessExecutionRole` are used.
* AgentCore spans in CloudWatch require Transaction Search, an account-level setting that this stack does not
  change.

## cdk-nag acknowledgements (AwsSolutions pack)

Defined in `infra/smarthome_infra/nag.py`; `cdk synth` reports no unacknowledged findings.

| Rule | Scope | Reason |
|---|---|---|
| IAM4 (AWSLambdaBasicExecutionRole) | Lambda roles | AWS managed policy limited to CloudWatch Logs writes; replace with inline policies in production. |
| IAM4 (AWSLambdaVPCAccessExecutionRole) | VPC Lambda roles | Required for ENI management of VPC-attached functions. |
| L1 | Functions | Functions use the newest Python runtime available in CDK at build time; the CDK custom-resource provider runtime is managed by CDK. |
| IAM5 `Resource::*` | Several | Actions without resource-level permissions: `iot:DescribeEndpoint`, `ecr:GetAuthorizationToken`, X-Ray writes, `logs:DescribeLogGroups`, `cloudwatch:PutMetricData` (namespace condition). |
| IAM5 table `/index/*` | Table grants | Generated by `Table.grant_*`; covers the table's own indexes. |
| IAM5 IoT topics `.../devices/*/cmd`, `/state`, `users/*/events`, `speakers/*/reply` | Publishing functions | Wildcard is the device/user/speaker id segment within the project prefix. |
| IAM5 `workload-identity-directory/default/workload-identity/*` | Runtime and gateway roles | Workload identities are created by AgentCore; names are unknown at synth time. |
| IAM5 `bedrock:*::foundation-model/<model>` | Runtime role | Cross-region inference profiles route to the same model in several regions. |
| IAM5 runtime log groups | Runtime role | Log groups are named by the service after the runtime id. |
| IAM5 `<runtime>/runtime-endpoint/*` | Orchestrator | Endpoints of this one runtime. |
| SMG4 | Both secrets | Rotation would need to update the API Gateway key / Cognito client in step; on the production checklist. |
| COG2 | User pool | Demo users only; MFA on the production checklist. |
| COG8 | User pool | Plus-tier threat protection out of prototype scope. |
| APIG4, COG4 | Platform API | Simulated existing platform protected with API key, usage plan and WAF; user-level authorisation inside the platform. |
